Most steppers ask you to declare the steps. This one measures and works them out, because the thing a layout actually depends on — how tall a field renders at this width — is not knowable when the markup is written. A short input and a four-row textarea are not the same height, and the answer changes with the container.

The contract is that the outer height never changes. Pages are split to fit that height, not the other way around.

## Height drives the split

The same six fields at three heights. The frame is whatever you asked for and never moves; the number of pages is whatever fits.

`height` takes a number (pixels) or any CSS length. The default is `min(28rem, 70vh)` — capped against the viewport so a short window can never push the footer, and therefore the only way to advance, off-screen. Only `mode="single"` accepts `height="auto"`.

## Page-sizing modes

`mode` decides how many fields go on a page.

- `fill` (default) packs each page with as many fields as fit. Fewest pages, but ragged — a tall field that follows three short ones lands on a page of its own.
- `uniform` gives every page the same number of fields, chosen so that even the tallest of them fits, then spreads the fields evenly across the resulting pages. Seven fields at three-per-page come out `3, 2, 2`, not `3, 3, 1`.
- `single` puts one field on every page. It measures nothing, so the page count is the field count. Because it does not split by height, it is the one mode that can take `height="auto"`.

## Gating a page

`canAdvance` receives the page being left and the keys of the fields on it. Return `false` to stay put, or a promise to gate on async validation — the primary action shows a loading state until it settles.

Validate the fields in `fieldKeys`, not the page number. Name each field with `fieldKey` on `MultiStepForm.Item`. Validate only that page's fields — checking the whole form would report errors on fields the person has not reached yet. Back is never gated.

## Custom chrome

`useMultiStepForm()` exposes the state and actions, so a surface can replace the footer entirely instead of prop-drilling `next` and `back`. It returns `step`, `stepCount`, `isFirstStep`, `isLastStep`, `isBusy`, `next`, `back`, `goTo`, `submit`, `visibleFieldKeys`, `gap`, and `mode`. `visibleFieldKeys` names the fields on the visible page and is empty until the first measurement.

## Anatomy

| Slot | Purpose |
| --- | --- |
| `Root` | Owns height, page state, and the advance gate. |
| `Header` / `Footer` | Fixed regions. Subtracted from the usable content height, never paged. |
| `Content` | The paged region. Each direct child is one indivisible block. |
| `Item` | Groups a label with its control so a split cannot fall between them. |
| `Actions` / `Back` / `Next` | Default controls. `Actions` accepts children to replace them. |
| `Counter` / `Progress` | The `2 of 5` readout and a hairline fill. Both hide on a single-page form. |

## Root Props

| Prop | Type | Default |
| --- | --- | --- |
| `height` | `number \| string` | `min(28rem, 70vh)` |
| `minHeight` / `maxHeight` | `number \| string` | `—` |
| `gap` | `number` | `8` |
| `mode` | `'fill' \| 'uniform' \| 'single'` | `'fill'` |
| `step` / `defaultStep` | `number` | `0` |
| `onStepChange` | `(step: number) => void` | `—` |
| `onSubmit` | `() => void \| Promise<void>` | `—` |
| `canAdvance` | `(step: number, fieldKeys: string[]) => boolean \| Promise<boolean>` | `—` |
| `presentation` | `'form' \| 'interactive'` | `'form'` |
| `primaryShortcut` | `(fieldKeys: string[], isLastStep: boolean) => 'enter' \| 'mod-enter'` | `—` |
| `primaryDisabled` | `boolean` | `false` |
| `className` | `string` | `—` |

`minHeight` and `maxHeight` bound a frame sized by `height="auto"`. A promise from `onSubmit` or `canAdvance` keeps the form busy until it settles. `presentation="interactive"` drops the bordered frame for the composer's slot layout and motion. `primaryShortcut` lets `Enter`, or `Cmd/Ctrl+Enter`, run the primary action for the visible fields; `primaryDisabled` turns that shortcut off.

## Slot Props

| Slot | Prop | Type | Default |
| --- | --- | --- | --- |
| `Item` | `fieldKey` | `string` | `—` |
| `Next` | `submitLabel` | `ReactNode` | `'Submit'` |
| `Next` | `hint` | `ReactNode` | `—` |
| `Next` | `disabled` | `boolean` | `false` |
| `Back` | `showOnFirstStep` | `boolean` | `false` |
| `Counter` | `format` | `(step: number, stepCount: number) => string` | `—` |
| `Counter` | `showWhenSingleStep` | `boolean` | `false` |
| `Content` | `sizing` | `'tallest' \| 'active'` | `'tallest'`, or `'active'` when interactive |

## Notes

- Every field stays mounted, on or off the visible page. Paging back never loses what was typed, and form-library registrations survive. Off-page fields are moved out of flow and made `inert`.
- Give dynamic children explicit keys so inserted, removed, or reordered items preserve state.
- A field taller than the page gets its own page, and that page scrolls.
- Default button labels are English literals. Pass translated nodes as children of `Back` and `Next`, and as `submitLabel`. Use `format` on `Counter` to customize the readout.
