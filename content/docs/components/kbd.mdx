## Keys

`keys` takes the keys of a shortcut in order. Modifier tokens become symbols: `mod` (or `meta`, `cmd`) shows `⌘` on Mac and `Ctrl` elsewhere, `alt` (or `option`) shows `⌥` or `Alt`, `shift` shows `⇧`, and `enter` shows `↵`. Any other token is shown as written. The server always renders the `Ctrl` and `Alt` labels, and Mac browsers switch to symbols after hydration.

Without `keys`, the keycap shows its `children`.

## Variants

`light` sits on page surfaces and secondary buttons. `dark` is for primary buttons. `disabled` dims either variant and sets `aria-disabled`.

## In a button

Put the keycap after the label with `ml-1`, and match `disabled` to the button. Add `aria-hidden` so screen readers don't read the shortcut as part of the button's name.

## Usage

```tsx
import { Button } from '@/components/ui/button';
import { Kbd } from '@/components/ui/kbd';

<Kbd keys={['mod', 'K']} />

<Button mode="primary" disabled={!canSave}>
  Save
  <Kbd aria-hidden className="ml-1" keys={['mod', 'enter']} variant="dark" disabled={!canSave} />
</Button>
```

## Properties

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `keys` | `string[]` | `—` | Key tokens in order, such as `['mod', 'K']`. Takes precedence over `children`. |
| `children` | `ReactNode` | `—` | Content to show when `keys` is not set. |
| `variant` | `'light' \| 'dark'` | `'light'` | Keycap style: `light` for surfaces and secondary buttons, `dark` for primary buttons. |
| `disabled` | `boolean` | `false` | Dims the keycap and sets `aria-disabled`. |
| `className` | `string` | `—` | Additional CSS classes, such as `ml-1` for spacing after a label. |
| `...props` | `ComponentProps<'kbd'>` | `—` | Other attributes, such as `aria-hidden`, are passed to the `kbd` element. |
